# 14. 奖状个性化功能实现

## 📋 概述

本次新增“奖状个性化”能力：**为每个用户上传一个角色形象图（character image）**，在周结算生成奖励时，系统会将该角色图合成到对应的奖状底图上，并将**合成后的奖状图片**写入 `rewards.certificate_url`（优先），若合成失败则回退为底图 URL。

## 🎯 功能清单

### 1. 用户角色图片字段

- **目标**：为用户保存一张“角色形象图”URL（通常为透明背景 PNG）。
- **数据库变更**：`User` 表新增字段 `character_image`（Prisma 字段名 `characterImage`）。

对应模型位置：`prisma/schema.prisma`

### 2. 管理端上传/查询用户角色图片

- **管理页面入口**：`/admin` → “用户角色”页签
- **能力**：
  - 输入 `userId` 并上传图片到 OSS
  - 回写用户的 `characterImage`
  - 支持按 `userId` 查询当前已配置的角色图 URL

### 3. 结算时生成个性化奖状

在 `settleWeekRanking` 中：

- **按排名选择底图**：冠军/亚军/季军/参与奖分别对应 `cert_configs` 的 `img_gold/img_silver/img_bronze/img_participate`
- **若用户存在 `characterImage` 且 OSS 配置完整**：
  - 下载底图与角色图
  - 使用 `sharp` 将角色图缩放并按固定坐标叠加到底图
  - 将合成结果上传至 OSS，并将上传 URL 写入 `rewards.certificate_url`
- **失败兜底**：
  - 合成失败或 OSS 不可用 → 使用底图 URL 作为 `certificate_url`

## 🗃️ 数据库结构

### 1. `User.characterImage`

- **字段**：`character_image`（Prisma：`characterImage`）
- **类型**：`VARCHAR(500)`，可为空
- **含义**：用户角色图的 OSS URL

## 🧩 核心实现

### 1. 图片合成模块

- **文件**：`lib/image-composite.ts`
- **函数**：`compositeCertificateImage(baseImageUrl, characterImageUrl)`
- **行为**：
  - 下载底图与角色图
  - 底图尺寸（推荐/基准）：`1280x1311`
  - 角色图缩放：`300x300`，`fit: 'contain'`，透明背景
  - 叠加坐标（像素）：
    - `left = 420`
    - `top = 670`
  - 输出格式：**保持底图原格式**（例如底图是 jpg，则输出 jpg）

### 2. 结算流程接入（生成并上传个性化奖状）

- **文件**：`lib/settlement.ts`
- **接入点**：在为每个获奖用户生成 `reward` 时，如果用户存在 `characterImage`，则执行合成并上传
- **输出格式处理（关键点）**：
  - 合成后通过 `sharp(metadata)` 读取结果格式
  - 上传 OSS 时按格式设置正确的文件扩展名与 `Content-Type`
  - 避免“底图 jpg 但强制以 png 上传”导致的格式不一致问题

## 🌐 API 接口

### 1. 上传用户角色图片

- **路径**：`POST /api/admin/user-character`
- **鉴权**：若设置 `ADMIN_SECRET`，需 `Authorization: Bearer <ADMIN_SECRET>`
- **请求体**：`FormData`
  - `userId`: string（用户 id）
  - `file`: File（图片文件）
- **限制**：
  - 文件类型必须为 `image/*`
  - 大小限制：5MB
- **返回**：上传后的图片 URL，并更新 `User.characterImage`

### 2. 获取用户角色图片

- **路径**：`GET /api/admin/user-character?userId=123`
- **鉴权**：同上（可选）
- **返回**：`userId / nickname / characterImage`

### 3. 结算接口（沿用既有接口）

- **路径**：`POST /api/admin/settle?week=xx&year=yyyy&force=false`
- **说明**：若用户已配置 `characterImage` 且 OSS 可用，结算生成的 `certificate_url` 将尽可能指向“合成后奖状”。

## 🖥️ 管理页面

- **文件**：`app/admin/page.tsx`
- **新增 UI**：
  - “用户角色”页签
  - 输入 `userId`、选择图片、上传、展示当前角色图 URL（若存在）

## ⚙️ 环境变量与依赖

### 1. OSS（必需，个性化合成上传才会生效）

需要配置（与其他上传功能共用）：

- `OSS_ACCESS_KEY_ID`
- `OSS_ACCESS_KEY_SECRET`
- `OSS_BUCKET`
- `OSS_REGION`
- `OSS_ENDPOINT`

未配置或初始化失败时：结算会回退为底图 URL，不影响主流程。

### 2. 管理接口鉴权（可选）

- `ADMIN_SECRET`
  - 设置后，管理类接口需要 `Authorization: Bearer <ADMIN_SECRET>`
  - 未设置则不校验（便于开发测试）

## ✅ 使用说明（推荐流程）

1. 在 `/admin` 的“用户角色”页签，为目标用户上传角色图（建议透明 PNG）。
2. 在 `/admin` 的“结算”页签触发结算指定周。
3. 查看 `rewards.certificate_url`：
   - 若为 `certificates/<weekNumber>/...` 路径：表示已生成并上传个性化奖状
   - 若仍为 `certs/<type>-...`：表示本次回退使用底图（常见原因：OSS 不可用/合成失败/用户未配置角色图）

## 🧯 常见问题与排查

1. **用户未生效**
   - 检查用户是否已配置 `User.characterImage`
   - 检查 OSS 环境变量是否完整

2. **合成失败但未中断结算**
   - 属于正常兜底：会自动使用底图 URL
   - 可查看服务端日志中 `图片合成失败` / `OSS 客户端初始化失败` 等输出

3. **合成图格式异常**
   - 已通过“按合成结果格式设置扩展名与 Content-Type”避免格式不一致
