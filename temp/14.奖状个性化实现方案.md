# 14. 奖状个性化实现方案

## 📋 需求概述

### 功能目标

实现每周奖状的个性化功能，让每个用户的奖状都包含其个人形象元素。

### 核心需求

1. **用户形象管理**
   - 管理员可以为每个用户上传一个透明的形象图片
   - 形象图片由设计师根据用户个人特征绘制
   - 图片需要支持透明背景（PNG格式）

2. **奖状合成**
   - 结算时，根据用户排名获取对应的底图（冠军/亚军/季军/参与奖）
   - 将用户形象图片与底图进行合成
   - 合成后的图片上传到OSS
   - 将合成图片的URL保存到 `rewards.certificate_url` 字段

3. **兼容性处理**
   - 如果用户没有上传形象图片，则使用底图作为奖状
   - 如果图片合成失败，回退到使用底图

---

## 🎨 设计思路

### 图片合成流程

```
用户形象图片（透明背景 PNG）
         ↓
    [图片合成]
         ↓
奖状底图（根据排名选择）
         ↓
   合成后的奖状图片
         ↓
   上传到 OSS
         ↓
保存 URL 到数据库
```

### 数据流

1. **管理员上传用户形象**
   - 上传图片 → OSS → 保存URL到 `users.character_image`

2. **结算时合成奖状**
   - 查询用户形象图片URL
   - 查询对应排名的底图URL
   - 下载两张图片
   - 合成图片
   - 上传合成后的图片到OSS
   - 保存合成图片URL到 `rewards.certificate_url`

---

## 🗄️ 数据库设计

### 1. 修改 User 表

**新增字段：**
- `character_image` (VARCHAR(500), nullable)
  - 存储用户形象图片的OSS URL
  - 允许为空（用户可能没有上传形象）

**字段说明：**
- 与 `avatar` 字段区分：`avatar` 是用户头像，`character_image` 是用于奖状合成的形象图片
- 支持透明背景的PNG格式图片

### 2. rewards 表（已存在）

**使用现有字段：**
- `certificate_url` (VARCHAR(500), nullable)
  - 存储合成后的奖状图片URL
  - 如果用户没有形象图片，存储底图URL
  - 如果合成失败，存储底图URL

---

## 🔧 技术方案

### 1. 图片处理库选择

**推荐使用：`sharp`**

**优势：**
- ✅ 性能优秀，基于 libvips
- ✅ 支持多种图片格式（PNG、JPEG、WebP等）
- ✅ 支持图片合成、缩放、裁剪等操作
- ✅ Node.js 生态成熟，文档完善
- ✅ 支持透明背景处理

**安装：**
```bash
npm install sharp
npm install --save-dev @types/sharp
```

### 2. 图片合成参数

**需要配置的参数：**
- `characterX`: 用户形象在底图上的X坐标（像素）
- `characterY`: 用户形象在底图上的Y坐标（像素）
- `characterWidth`: 用户形象宽度（像素）
- `characterHeight`: 用户形象高度（像素）

**参数调整策略：**
- 不同排名的底图可能需要不同的参数
- 建议先测试一张底图，确定合适的参数
- 可以考虑将参数配置化（存储在数据库或配置文件中）

### 3. OSS 存储路径

**建议的路径结构：**
- 用户形象：`characters/{userId}-{timestamp}.png`
- 合成奖状：`certificates/{weekNumber}-{userId}-{rank}.png`

**命名规则说明：**
- 用户形象：包含用户ID和时间戳，便于管理
- 合成奖状：包含周编号、用户ID和排名，便于查找和去重

## 📝 实现步骤

### 步骤 1: 数据库迁移

1. 修改 `prisma/schema.prisma`，在 `User` 模型中添加 `characterImage` 字段
2. 执行迁移：`npx prisma migrate dev --name add_user_character_image`
3. 生成 Prisma Client：`npx prisma generate`

### 步骤 2: 安装依赖

安装图片处理库：
```bash
npm install sharp
npm install --save-dev @types/sharp
```

### 步骤 3: 创建用户形象上传 API

**API 路径：** `POST /api/admin/user-character?userId={userId}`

**功能：**
- 验证管理员权限
- 验证用户是否存在
- 验证上传的文件（类型、大小）
- 上传图片到OSS
- 更新用户表中的 `character_image` 字段

**请求参数：**
- `userId`: 用户ID（查询参数）
- `file`: 图片文件（FormData）

**响应：**
- 成功：返回图片URL
- 失败：返回错误信息

### 步骤 4: 创建图片合成工具函数

**文件：** `lib/image-composite.ts`

**功能：**
- 下载底图（从OSS URL）
- 下载用户形象图片（从OSS URL）
- 使用 sharp 合成两张图片
- 返回合成后的图片Buffer

**函数签名：**
```typescript
compositeCertificate(
  baseImageUrl: string,
  characterImageUrl: string,
  options: {
    characterX?: number
    characterY?: number
    characterWidth?: number
    characterHeight?: number
  }
): Promise<Buffer>
```

**合成逻辑：**
1. 下载底图并获取尺寸
2. 下载用户形象图片
3. 根据参数调整用户形象大小和位置
4. 将用户形象合成到底图上
5. 输出PNG格式的合成图片

### 步骤 5: 修改结算逻辑

**文件：** `lib/settlement.ts`

**修改位置：** 在 `settleWeekRanking` 函数中，创建 reward 记录之前

**修改逻辑：**
1. 获取用户信息（包含 `character_image` 字段）
2. 判断用户是否有形象图片
3. 如果有形象图片：
   - 调用图片合成函数
   - 上传合成后的图片到OSS
   - 使用合成图片URL作为 `certificate_url`
4. 如果没有形象图片或合成失败：
   - 使用底图URL作为 `certificate_url`

**错误处理：**
- 如果图片下载失败，使用底图
- 如果图片合成失败，使用底图
- 如果OSS上传失败，记录错误日志，使用底图

### 步骤 6: 管理员页面上传功能

**位置：** `app/admin/page.tsx`

**功能：**
- 在用户列表中添加"上传形象"按钮
- 点击后弹出文件选择对话框
- 上传成功后刷新用户列表或显示成功提示

**UI建议：**
- 显示当前用户是否已有形象图片
- 支持预览已上传的形象图片
- 支持重新上传（覆盖旧图片）

| 参数 | 说明 | 示例值 |
|------|------|--------|

2. **参数配置化**
   - 可以将参数存储在 `cert_configs` 表中
   - 或者创建新的配置表存储合成参数

3. **测试流程**
   - 先使用一张测试底图和测试形象图片
   - 调整参数直到效果满意
   - 记录参数值用于生产环境

## ⚠️ 注意事项

### 1. 图片格式要求

- **用户形象图片**：必须使用PNG格式，支持透明背景
- **底图**：支持PNG、JPEG等格式
- **合成后的图片**：建议使用PNG格式，保持透明效果

### 2. 图片大小控制

- **上传限制**：用户形象图片建议限制在5MB以内
- **合成后大小**：控制合成后图片的大小，避免过大
- **压缩优化**：可以考虑对合成后的图片进行压缩

### 3. 性能考虑

- **异步处理**：结算时可能需要合成多张图片，考虑使用异步处理
- **批量处理**：可以使用 `Promise.all` 并行处理多张图片
- **缓存机制**：如果同一用户多次结算，可以考虑缓存合成结果

### 4. 错误处理

- **下载失败**：如果图片下载失败，使用底图作为奖状
- **合成失败**：如果图片合成失败，使用底图作为奖状
- **上传失败**：如果OSS上传失败，记录错误日志，使用底图
- **用户无形象**：如果用户没有上传形象图片，直接使用底图

### 5. 存储成本

- **OSS存储**：合成后的图片会占用OSS存储空间
- **清理策略**：可以考虑定期清理旧的合成图片（如果用户重新结算）
- **去重机制**：使用包含周编号、用户ID、排名的文件名，避免重复生成
